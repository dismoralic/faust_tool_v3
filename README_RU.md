# Faust Tool v3

Telegram-юзербот на Telethon с удалённой Ollama, безопасными AI-действиями и совместимым загрузчиком FTG-модулей.

## Обновление 3.5.1

Название проекта и архива остаётся v3. Перед обновлением останови юзербота и сделай копию его папки.
Замени программные файлы, но сохрани свои `userbot/config.json`, `userbot/botconfig.json`,
`userbot/ai/settings.json`, папки `userbot/sessions`, `userbot/data` и установленные пользователем модули.
Запуск прежний: `python -m userbot.userbot` на Windows, `python3 -m userbot.userbot` на Ubuntu.

После перезапуска вызови новую `.panel` в нужном чате: старые панели не сохраняют привязку между запусками.
В интерфейсе видны название и ID чата, чтобы не переключить другой диалог по ошибке.

### Автоответ кнопками

1. Напиши `.panel` в личном диалоге или группе, где нужны ответы.
2. Открой «Автоответ» → «Этот чат» или «Для всех».
3. Выбери «ВКЛ: от моего имени», «ВКЛ: AI-ассистент» или «Выключить автоответ».

Включение выбирает один режим для выбранной области. Выключение этого чата создаёт явное исключение:
общий автоответ и старый `.answer` больше не могут его обойти. Остальные чаты не меняются.
«Для всех → Выключить» отключает оба режима во всех чатах, включая старые индивидуальные включения и `.answer`.
Включение общего режима сохраняет исключения; для их отмены включи автоответ в конкретном чате.
Индивидуальные правила важнее общих; при равном приоритете выбирается persona.

Настройки сохраняются сразу. Ожидающие отправки для изменённой области отменяются, даже если модель
уже генерирует ответ или закончила его и ждёт общей паузы. Уже переданный Telegram запрос отозвать нельзя.
Ручной вызов inline-бота без `.panel` не сообщает точный ID назначения: для «Этот чат» требуется `.panel`.
Бот по-прежнему принимает кнопки только от владельца. Публичная группа должна разрешать inline-сообщения.

### Исправление повторяющихся ответов

- История передаётся Ollama отдельными репликами user/assistant, а не единой цитатой для продолжения текста.
- Текущее сообщение не дублируется. История остаётся в хронологическом порядке, даже когда в очереди несколько сообщений.
- Для стиля отдельно выбираются реальные реплики владельца. Автоответы, команды, inline-панели и пересланные сообщения не используются как образцы.
- Старый кэш сохраняется, но сообщения без достоверной метки происхождения не считаются стилевыми образцами. После обновления несколько твоих обычных реплик помогут сформировать чистый образец.
- Явное эхо и повтор предыдущего автоответа приводят максимум к одной дополнительной генерации. Если она тоже неудачна, сообщение пропускается с причиной в логе; постоянная заглушка больше не отправляется.
- Обычный ответ требует одного запроса. Хранятся последние 100 сообщений, а для короткого ответа модель получает компактный недавний контекст и до пяти реальных стилевых образцов. Полная история обновляется не чаще раза в сутки.

Это исправления логики и контекста, а не гарантия качества qwen3:1.7b: маленькая модель всё ещё может ошибаться.
Автотесты проверяют правила, очереди, реальные объекты Telethon и HTTP-обмен с локальным тестовым сервером.
Живая сессия Telegram и модель на VPS в тестах не используются.

## Что изменено

- В архиве нет Telegram-сессии, старых логов и модуля `Cu.py`.
- Перед запуском выполняется настоящий запрос к `qwen3:1.7b`: модель должна вернуть ровно `1234`.
- При недоступной Ollama запуск останавливается без удаления каких-либо файлов.
- Запросы к Ollama идут через одну очередь, потому что сервер работает на CPU с `OLLAMA_NUM_PARALLEL=1`.
- Есть лимит частоты запросов на пользователя, история диалога и статистика скорости. Суточного лимита нет.
- Одна и та же `qwen3:1.7b` отвечает пользователю и выбирает действия: переключения между моделями больше нет.
- Каждый запрос `.фауст` всегда передаётся `qwen3:1.7b` вместе с полным каталогом действий: локального допуска по ключевым словам и узким шаблонам больше нет.
- Если действие не требуется, этот же запрос сразу содержит обычный ответ — второй вызов Ollama не выполняется.
- Локальные фразы-триггеры не выполняют действия напрямую: окончательное решение принимает нейросеть-маршрутизатор.
- Разговорные формулировки, местоимения и опечатки разрешены. Если модель не уверена либо не хватает обязательных данных, действие не выполняется: Faust задаёт уточняющий вопрос и предлагает до трёх похожих готовых команд.
- Во время обработки исходящая команда оформляется HTML-цитатой: заголовок выделяется жирным, запрос показывается моноширинно, состояние — курсивом.
- Маршрутизатор не может подставить пользователя или чат, которого нет в исходном запросе.
- Сетевые сбои повторяются автоматически, а circuit breaker временно прекращает запросы после серии ошибок.
- История ограничивается размером контекста; запросы одного чата выполняются последовательно и не перемешиваются.
- Опасные AI-действия не выполняются без одноразового `.confirm КОД`.
- Цепочки вроде «скачай файл под ярлыком договор и скинь Артему» подтверждаются один раз и выполняются строго по порядку.
- Файлы сохраняются в `userbot/data/files`, а ярлыки — в `userbot/data/file_library.json`; получателя можно задавать username, ID или видимым именем из диалогов.
- Есть два новых автоответчика: имитация стиля владельца и явно подписанный `AI-ассистент`. Области: все, чат, пользователь, контакты и не контакты.
- Все автоответы проходят через одну глобальную очередь с паузой 5 секунд. Для каждого активного чата хранится до 100 сообщений; полное обновление контекста выполняется не чаще одного раза в сутки.
- Сгенерированные автоответы помечаются отдельно и не используются как образец стиля владельца. Эхо и зацикленные фразы проверяются перед отправкой; возможна одна дополнительная генерация.
- При пустом или отсутствующем `userbot/botconfig.json` юзербот автоматически создаёт через BotFather личного бота `faust-tool` с уникальным username вида `fausttool_xxxxxx_bot`.
- Личный бот запускается вторым Telethon-клиентом в том же процессе, включает inline-панель и принимает кнопки только от владельца.
- Если inline-режим запрещён или недоступен в выбранном чате, `.panel` показывает причину и переключает управление на команды.
- Справка оформлена HTML-цитатами и разделена на системные, AI, модульные, FTG и panel-команды.
- FTG-команды принимаются только из исходящих сообщений владельца.
- Модули сначала помещаются в карантин, проверяются, получают SHA-256 и устанавливаются только после `.modconfirm КОД`.
- Повторная загрузка модулей удаляет старые handlers и фоновые задачи.

## Быстрая установка на Windows

1. На странице GitHub нажми `Code` → `Download ZIP` и распакуй архив.
2. Запусти `install_windows.bat` двойным щелчком.
3. Введи `API_ID`, `API_HASH`, адрес Ollama и название модели.
4. При первом запуске введи номер телефона, код Telegram и пароль двухэтапной аутентификации, если он включён.

Установщик проверяет Python 3.10+, при необходимости предлагает автоматическую установку Python 3.12 через `winget`, создаёт `.venv`, ставит зависимости и запускает мастер конфигурации. Для следующих запусков используй `start_windows.bat`.

## Быстрая установка в Termux

Скопируй целиком единственную строку из `TERMUX_COMMAND.txt` и вставь её в Termux. При первой установке команда запросит HTTPS-ссылку на GitHub-репозиторий, установит системные пакеты, клонирует проект, создаст `.venv`, запросит настройки и запустит Faust Tool.

Если репозиторий уже находится в `$HOME/faust_tool_v3`, та же команда выполнит безопасный `git pull --ff-only` и повторно проверит зависимости. Существующая конфигурация, сессия и пользовательские данные не перезаписываются.

После установки можно запускать проект короткой командой:

```bash
cd "$HOME/faust_tool_v3" && bash start_termux.sh
```

## Установка на Ubuntu без виртуального окружения

```bash
sudo apt update
sudo apt install -y python3 python3-pip
cd /var/faust_tool_v3
python3 -m pip install --break-system-packages -r requirements.txt
python3 setup_config.py
python3 -m userbot.userbot
```

При первом запуске Telethon попросит номер телефона, код Telegram и пароль двухэтапной аутентификации, если он включён. Сессия будет создана в `userbot/sessions/faust.session` с правами `600`.

После входа юзербот проверяет `userbot/botconfig.json`. Если файл пустой, он самостоятельно:

1. открывает диалог с `@BotFather`;
2. создаёт `faust-tool` с уникальным username;
3. сохраняет токен в `botconfig.json` с правами `600`;
4. включает inline-режим и задаёт команды бота;
5. запускает бота и отправляет ему `/start`;
6. получает от бота сообщение о завершении первичной настройки.

У аккаунта должен быть доступ к `@BotFather` и свободный лимит создания ботов. Ошибка регистрации не останавливает основной юзербот: остаётся командная панель. Не удаляй заполненный `botconfig.json`, иначе при следующем запуске будет предпринята попытка создать нового бота; старый бот при этом автоматически не удаляется.

Не запускай одну и ту же сессию одновременно на двух IP-адресах. Не отправляй файл сессии другим людям и не добавляй его в архивы.

Публичная версия не должна содержать `userbot/config.json`, `userbot/botconfig.json`, `userbot/sessions`, `userbot/logs`, `userbot/data`, `userbot/ai/settings.json` и `userbot/ai/actions_audit.jsonl`. Они создаются локально и уже добавлены в `.gitignore`.

## Конфигурация

Главный файл: `userbot/config.json`. Он создаётся командой `python setup_config.py` из безопасного шаблона `userbot/config.example.json`.

Проверь эти значения:

```json
{
  "ollama_url": "http://87.120.84.247:11434",
  "model": "qwen3:1.7b",
  "ollama": {
    "keep_alive": "30m",
    "retry_attempts": 1,
    "circuit_threshold": 3,
    "circuit_seconds": 30
  }
}
```

Если адрес VPS изменится, замени `ollama_url` на `http://IP_ТВОЕГО_VPS:11434`.

Настройки рассчитаны на 2 vCPU и 4 ГБ RAM:

- `num_ctx`: 2048;
- `num_predict`: 256;
- `keep_alive`: 30 минут, чтобы модель не выгружалась между командами;
- параллельных генераций: 1;
- тайм-аут: 120 секунд;
- суточных ограничений количества запросов нет.

Для CPU-сервера рекомендуется добавить в секцию `[Service]` файла
`/etc/systemd/system/ollama.service` следующие строки:

```ini
Environment="OLLAMA_KEEP_ALIVE=30m"
Environment="OLLAMA_NUM_PARALLEL=1"
Environment="OLLAMA_MAX_LOADED_MODELS=1"
```

После изменения выполни `systemctl daemon-reload && systemctl restart ollama`.

## Личная inline-панель

Команда `.panel` запрашивает у личного бота inline-результат и отправляет панель в текущий чат. Боту необязательно состоять в этом чате. Главное меню сокращено до разделов AI, модули, автоответ, файлы и система; подробные кнопки находятся внутри разделов. В разделе «Автоответ» кнопками включаются и выключаются оба режима либо глобально, либо только для того чата, где была вызвана `.panel`.

Если Telegram запретил inline-вызов в конкретном чате, исходная команда превращается в сообщение с причиной и доступными командами. После этого работают `.panel status`, `.panel health`, `.panel ai`, `.panel modules`, `.panel actions` и `.panel reload`. Команда `.panel retry` повторяет попытку открыть кнопки.

Другие пользователи могут видеть отправленную панель, но выполнить действия не смогут: каждый callback сверяет Telegram ID с владельцем юзербота.

Автоответы по умолчанию выключены. Старый `.answer` при `auto_answer_private_only: true` работает только в личных сообщениях. Новые правила `.autoreply` поддерживают также группы и имеют приоритет над старым режимом.

`persona` использует контекст последних сообщений чата и реальные образцы стиля владельца. Ответы, ранее созданные нейросетью, из стилевого образца исключаются. Проверка отбрасывает явное эхо и подозрительные повторяющиеся фразы. `assistant` не выдаёт себя за владельца и начинает ответ с `AI-ассистент:`. Индивидуальные правила важнее общих; при равном приоритете выбирается `persona`.

Контекст находится в `userbot/data/autoreply_contexts`. При первом сообщении в активном чате он создаётся, затем дополняется новыми сообщениями; полный запрос последних 100 сообщений повторяется максимум раз в 24 часа.

`answer` разрешает пользователю получать обычные ответы AI. `bypass` отдельно разрешает пользователю вызывать AI-действия. Владелец всегда имеет доступ к действиям.

Формат обмена сверялся с официальными описаниями [Ollama /api/chat](https://docs.ollama.com/api/chat)
и [событий Telethon](https://docs.telethon.dev/en/stable/modules/events.html).

## Файлы и цепочки действий

Ответь на документ, фото, видео или другое медиа:

```text
.фауст сохрани этот файл с ярлыком договор
```

После сохранения файл доступен и после перезапуска:

```text
.фауст скинь файл договор Артему
.фауст отправь сохраненный файл договор пользователю 123456
.files
```

Имя ищется в последних диалогах. Если найдено несколько похожих имён, Faust не будет угадывать и покажет их ID. Команда может сразу содержать цепочку: `.фауст скачай этот файл под ярлыком договор и скинь его Артему`.

Для действий «перешли», «закрепи», «открепи» и «удали это моё сообщение» команда должна быть отправлена реплаем на нужное сообщение. Полное удаление чужих сообщений через AI намеренно не реализовано.

Изменяющие и опасные действия сначала покажут план:

```text
Требуется подтверждение...
.confirm A1B2
```

Подтверждение действует две минуты и принадлежит только тому пользователю, который создал действие.

## FTG-модули

Поддерживаются основные элементы FTG/Hikka-модулей:

- `loader.Module`, `loader.tds`;
- `loader.command`, методы `*cmd` и словарь `commands`;
- `loader.watcher` и методы `*watcher`;
- `loader.tag` с `no_commands`, `only_commands`, `only_pm`, `only_groups`, `only_channels`, `in`, `out`, `regex`;
- `loader.loop` с `start/stop`;
- `client_ready`, `on_dlmod`, `on_unload`;
- `ModuleConfig`, старый формат конфигов FTG, сохранение значений, `ConfigValue`, `on_change`, основные `validators`;
- основные security-декораторы Hikka/FTG (`owner`, `sudo`, `support`, group-права, `pm`, `everyone`);
- `raw_handler`, базовый `callback_handler`, совместимые типы `inline.types`;
- `self.strings("key")`, `self._client`, `self.client`, `self._db`;
- `self.get`, `self.set`, сохраняемый `self.pointer`, `self.lookup`, `self.invoke`, `self.request_join`;
- `utils.get_args_raw`, `utils.get_kwargs`, `utils.answer`, `utils.remove_html`, `utils.smart_split` и другие базовые helpers.

Полная совместимость со всеми Hikka/FTG-модулями невозможна без самой Hikka: сложные inline-формы, собственные библиотеки и специфические внутренние API могут потребовать адаптацию.

### Установка модуля

Ответь командой `.dlmod` на файл `.py` либо передай HTTPS-ссылку:

```text
.dlmod https://example.org/module.py
.modconfirm КОД
```

Для native-модуля используется `.dlnative`.

Команды управления:

```text
.modules
.reloadmod <имя>
.unloadmod <имя>
.ftgconfig <имя>
.ftgconfig <имя> <ключ> <значение>
.modcancel
```

Значения `ModuleConfig` сохраняются в `userbot/data/ftg_db.json` и восстанавливаются после перезапуска. Циклы `loader.loop` автоматически запускаются только при `autostart=True`; вручную запущенные циклы корректно останавливаются при выгрузке.

Статическая проверка не гарантирует безопасность Python-модуля. После подтверждения модуль получает доступ к Telegram-аккаунту и файлам процесса. Устанавливай только код, который прочитал и которому доверяешь.

## Запуск через systemd

Сначала один раз запусти юзербот вручную и войди в Telegram. После появления файла сессии:

```bash
sudo cp faust-userbot.service.example /etc/systemd/system/faust-userbot.service
sudo systemctl daemon-reload
sudo systemctl enable --now faust-userbot
sudo systemctl status faust-userbot --no-pager
```

Логи:

```bash
journalctl -u faust-userbot -f
```

Если проект лежит не в `/var/faust_tool_v3`, измени `WorkingDirectory` в service-файле.

## Проверка после установки зависимостей

```bash
cd /var/faust_tool_v3
python3 -m unittest discover -v
python3 -m compileall -q userbot
```
